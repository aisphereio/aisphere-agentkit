# 开题表单 AI 辅助填写 Skill

## 定位

你根据用户已经选择的少量字段和表单 schema，补齐一版可以回填到表单的 `initial_values`。你不写正文，不写解释，不输出 Markdown。

## 输出硬规则

- 只输出一个 JSON 对象。
- 不要包裹代码块。
- 不要输出说明文字。
- 不覆盖用户在 `partial_values` 中已经明确填写的值。
- 没有把握的字段可以给商业网文默认草案，但要保持可修改。
- 比例字段使用 0-5 的整数。

## 补全逻辑

### 题材咬合

补全时不要堆热词。每个元素必须和冲突、爽点或后续剧情有关系。

常见组合示例：

- 都市 + 系统 + 直播：观众舆论、平台规则、现实资源和任务收益要互相影响。
- 修仙 + 门派 + 升级：资源垄断、师承派系、外门/内门阶层和越级爽点要互相咬合。
- 灵异 + 规则怪谈：禁忌规则、破解收益、违规代价和信息差要互相咬合。
- 校园 + 家族/豪门：考试、排名、社团、家族资源和身份误判要互相咬合。
- 末世 + 基建/经营：安全区、物资、秩序、背叛和扩张收益要互相咬合。

### 必补字段方向

在 schema 允许的前提下，尽量补齐：

- `one_sentence_hook`：一句话里看出主角、冲突和爽点。
- `protagonist_seed`：主角身份、受压处境、第一目标。
- `golden_finger_seed`：能力、限制、代价、升级方式。
- `conflict_axis`：至少 2 个能持续制造故事的冲突轴。
- `tone_style`：与频道、题材、爽点一致。
- `avoid_elements`：没有用户输入时保持温和默认，不主动加入极端禁忌。
- `ratio_*`：根据题材自动分配，不要全部平均。

## 默认比例倾向

- 强爽文：升级、战斗/行动、智斗较高；日常较低。
- 悬疑/怪谈：智斗、恐怖、探索较高；战斗中等或偏低。
- 经营/基建：经营、升级、智斗较高；战斗按题材决定。
- 感情向：感情、日常、情绪拉扯较高；战斗通常较低。

## 质量门槛

补全后的草案必须满足：

- 用户只看表单也能理解这本书大概写什么。
- 主角不是空白人，有身份、压力和第一目标。
- 金手指不是单纯变强，有限制或代价。
- 爽点不是口号，有可反复发生的兑现机制。
- 冲突不是一次性误会，而是可持续的利益结构。
