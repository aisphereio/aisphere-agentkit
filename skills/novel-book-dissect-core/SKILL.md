# 小说拆书核心 Skill

## 定位

本 Skill 只提供拆书方法论，不负责确定性文件处理。编码识别、切章、manifest、章节读取、边界修正必须交给 BookPreprocessorToolset。

拆书的目标不是“总结剧情”，而是反向工程作者的写作系统：章节为什么这样安排、信息为什么这样释放、爽点为什么这样铺垫、伏笔为什么这样延迟、章尾为什么能拉读者继续读。

## 拆书总原则

1. 先确认文本来源和章节 manifest，再分析章节。
2. 每次分析尽量限定在单章或相邻章节，避免凭空推断全书。
3. 把“剧情事实”和“写法判断”分开。
4. 把“这一章写了什么”和“这一章在全书中承担什么功能”分开。
5. 不追求文学鉴赏式评价，要提炼可复用的网文写作技法。
6. 所有技法必须能落到写作动作，例如：开局制造债务、章尾留下未兑现问题、先压后爽、用小胜利包装大危机。

## 标准拆解维度

每章至少拆以下内容：

- 一句话剧情摘要
- 本章核心功能
- 开头钩子
- 结尾钩子
- 表层冲突
- 深层冲突
- 主角状态变化
- 人物关系变化
- 新增信息
- 新增伏笔
- 强化伏笔
- 回收伏笔
- 爽点或期待感
- 压迫感来源
- 读者继续阅读的理由
- 可学习技法
- 可复用模板

## 禁止事项

- 禁止只做剧情摘要。
- 禁止在没有文本证据时判断全书结构。
- 禁止大段复制原文。
- 禁止把“好看、精彩、节奏快”这种空话当分析。
- 禁止把确定性切章任务交给大模型自行处理。
