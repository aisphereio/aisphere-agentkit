# 小说写作技法提炼 Skill

## 目标

从章节分析、章间关系和阶段 arc 中提炼可迁移的写作方法，形成可以挂载到其他小说创作 Agent 的 Skill 文档。

## 提炼原则

1. 技法必须脱离原书剧情也能复用。
2. 技法必须包含适用场景、操作步骤、风险和示例结构。
3. 不复制原书设定，不复刻角色和情节。
4. 重点提炼“结构动作”，而不是“剧情内容”。
5. 最终 Skill 的读者是外部写作 Agent，不是本项目读者；写法必须让另一个 Agent 只加载该 Skill 就能写出相近质量的文本。
6. 来源书、章节号、批次进度只允许放在 analysis / evaluation / metadata，不要放进正式 Skill 正文作为主体结构。

## Skill 训练目标卡

启动长任务前必须先确定训练目标卡。没有目标卡时，不要直接把一本书总结成一个大 Skill。

目标卡字段：

```json
{
  "skill_id": "novel-dialogue-power-gap",
  "skill_focus": "dialogue",
  "target_technique": "通过对白体现权力差",
  "abstraction_level": "atomic_technique",
  "transfer_scope": "可迁移到都市、玄幻、职场、家族、门派、官场、商战等权力不对等场景",
  "runtime_body_policy": "source_free",
  "evidence_policy": "metadata_only",
  "non_goals": [
    "不要提炼源书题材背景",
    "不要提炼源书人物设定",
    "不要输出章节总结",
    "不要把书名、章节号、角色名、地名写入正式 Skill 正文"
  ]
}
```

## 技法原子化规则

正式 Skill 优先沉淀“单一稳定动作”，不要把题材、世界观、剧情类型、章节功能混成一个大 Skill。

错误示例：

- 历史商战小说对话写作篇
- 某本书前五章综合技法
- 大清背景下的危机叙事方法

正确示例：

- 权力差对白法
- 隐藏筹码反转法
- 公开压制后的证据反打法
- 多人场景中的发言权分层法

## 去背景化转换规则

从源书提炼时，必须把内容转换为功能角色和结构动作：

- 具体角色名 → 上位者 / 下位者 / 被误判者 / 资源持有者 / 评价者 / 旁观者
- 具体组织名 → 规则密集型组织 / 高压行业环境 / 权力中心
- 具体地点名 → 公开社交场 / 私密谈判场 / 高压审判场 / 资源分配场
- 具体桥段 → 压力建立 / 回应延迟 / 权力确认 / 反击兑现 / 旁观者校准

正式 Skill 只能保留功能角色和结构动作，不能保留源书角色、地名、组织名、桥段名。

## 权力差对白提炼目标

当训练目标是 `novel-dialogue-power-gap` 时，只提炼以下问题：

> 如何用对白长度、回应速度、命令权、评价权、沉默权和旁观者反应，让读者不靠旁白说明也能感到谁压着谁。

必须观察的证据维度：

1. 谁能用短句、半句、沉默完成压迫。
2. 谁必须解释、补充、请示、立刻行动。
3. 谁拥有评价别人表现的资格。
4. 谁的话能改变场面秩序。
5. 旁观者如何通过安静、错愕、退让、改口来确认权力差。

必须丢弃：时代背景、商业制度、门派制度、家族设定、角色姓名、地点名、原书事件顺序。

## 技法输出格式

每个技法建议包含：

- 技法名称
- 解决的问题
- 适用场景
- 操作步骤
- 读者心理机制
- 可复用模板
- 使用风险
- 与其他技法的组合方式

## 正式 Skill 输出要求

当输出 `skill version` 或准备发布真实 Skill 草稿时，必须写成可执行的 `SKILL.md`，而不是“技法目录”或“项目进度摘要”。

允许的正文结构：

- 触发条件：什么时候该使用这个 Skill。
- 写作目标：读者应感受到什么权力关系、信息差或情绪压力。
- 核心原则：3-6 条可迁移判断。
- 执行流程：从场景判断、角色权力差、信息持有、对白推进到收束的步骤。
- 技法模块：每个模块包含适用场景、操作步骤、可替换模板、失败模式、验收标准。
- 反过拟合规则：明确丢弃书名、角色名、地名、历史设定、原文桥段和章节索引。
- 自检清单：写完后如何判断对话是否真的体现权力博弈。

禁止的正文结构：

- “从《某书》中提炼……”
- “已处理 15 章 / 258 章”
- “证据章节表”
- “质量检查摘要”作为 Skill 主体
- 只列 20 条技法名称，但不给外部 Agent 可执行步骤
- 把章节号、人物名、原书设定写成通用规则

## 示例

```markdown
## 技法：先压后爽的小闭环

### 解决的问题
章节中爽点来得太平，没有释放感。

### 适用场景
主角要完成第一次反击、打脸、能力展示、资源兑现时。

### 操作步骤
1. 先给主角一个公开压力或羞辱。
2. 让读者明确知道主角有可能赢，但场内角色不知道。
3. 延迟兑现，让压力再堆一层。
4. 用一个清晰动作释放结果。
5. 释放后立刻引出更大的新问题，避免章节结束后泄气。

### 风险
压制过长会憋屈，释放过短会不爽。需要保证每次压制都有明确回报。
```
