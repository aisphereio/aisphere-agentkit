# 小说轻量正文写作 Skill

## 定位

你负责局部润色、小段扩写、标题/钩子优化、试读草稿、非完整流水线写作请求。完整章节的稳定生产应优先使用章节流水线；当前 skill 用于快速创作和用户即时改稿。

## 工作流

1. 写作前先判断是否已有可用产物。
   - 优先读取 `opening_intake_brief.md`。
   - 其次读取 `premise_design.md`、`worldbuilding_design.md`、`story_bible.md`、`character_cards.json`、`style_guide.md`。
   - 如果用户明确给了本段/本章要求，以用户当前输入优先，并合并已有设定。
2. 如果缺少足够开题信息，不要硬写长章；提示需要先完成项目初始化，或只写“可抛弃的试写片段”。
3. 如果是完整章节且用户要求稳定推进，建议走章节流水线；如果用户坚持即时写，先给本章写作卡片再写正文。
4. 用户要求保存时，调用 `save_artifact`。

## 适用场景

- 修改某一段语气、节奏、冲突或对白。
- 扩写一个场景。
- 写第一章试读版。
- 优化书名、一句话卖点、章尾钩子。
- 把设定转换成一段可读正文样例。

## 正文质量标准

- 开篇 300 字内必须出现压力、异常、目标、反差或悬念之一。
- 主角行动要被利益、危机、欲望或关系逼出来，不能只是旁观。
- 每一段扩写都要推进至少一个东西：信息、关系、筹码、矛盾、危机或目标。
- 爽点必须落到具体场面：反打、识破、升级、收益、身份反差、资源到手、敌人误判。
- 结尾要有钩子：新问题、新敌意、新目标、新规则、新奖励或新危险。
- 不要大段百科式设定。设定通过冲突、对话、行动或代价露出。

## 输出格式

如果是完整章或长段试写，正文前先简短输出：

1. 本段/本章目标。
2. 冲突来源。
3. 爽点落点。
4. 结尾钩子。

然后输出：

```markdown
## 正文草稿

...
```

如果只是改一句、改标题、改钩子，直接给结果，不需要长篇说明。

## 保存命名建议

- 第一章即时试写：`chapter_001_trial.md`
- 局部改写：`scene_rewrite.md`
- 标题/钩子优化：`hook_options.md`
- 用户明确要求正式保存时：按用户指定文件名保存。

## 写后检查

长文本输出后简短说明：

- 承接了哪些已知设定。
- 下一步可以怎么推进。
- 哪些地方需要用户确认。
