# 小说人物与对话拆书 Skill

## 1. Skill 定位

本 Skill 用于从已切分小说章节中，提炼可迁移的写作技法，重点关注：

* 人物塑造
* 对话描写
* 人物关系
* 场景冲突
* 潜台词
* 情绪转折
* 信息释放
* 读者期待

本 Skill 不用于复述小说剧情，不用于摘抄原文，不用于总结读后感。

它的目标是把小说章节拆成“别人也能学会、能迁移到新作品里的写作方法”。

---

## 2. 核心原则

### 2.1 人物不是设定表，而是行为模式

拆书时不要只记录：

* 他是谁
* 他什么身份
* 他性格如何
* 他经历了什么

而要拆：

* 他此刻想要什么
* 他害怕失去什么
* 他在遮掩什么
* 他什么时候露出破绽
* 他面对不同关系时有什么不同反应
* 他的语言和动作如何暴露他

人物不是“善良、自卑、强势、冷漠”这些形容词。

人物必须被拆成可观察行为。

错误拆法：

```text
这个人物很自卑。
```

正确拆法：

```text
这个人物在被夸奖时第一反应是否认；在集体场合主动坐到边缘位置；被问到成就时会转移话题。这些行为共同构成“自我价值感不足”的人物表现。
```

---

### 2.2 对话不是聊天记录，而是人物之间的动作

拆对话时不要只看台词内容，要看台词在做什么。

每一句有效对话都应该具备动作性：

* 试探
* 遮掩
* 逼问
* 反击
* 退让
* 转移
* 求助
* 威胁
* 诱导
* 定义局面
* 争夺关系位置

错误拆法：

```text
这段对话写出了人物的矛盾。
```

正确拆法：

```text
这段对话的推进方式是：一方先用轻描淡写隐藏真实需求，另一方通过反问逼迫其表态；当秘密接近暴露时，前者转移话题，后者抓住破绽继续压迫，最终关系从试探进入对抗。
```

---

### 2.3 好对话必须有两层

每段对话都要拆出：

```text
表层话语：人物说了什么
深层意图：人物真正想达成什么
```

常见潜台词类型：

* 我担心你，但我不想显得软弱
* 我需要你帮忙，但我不想低头
* 我知道你撒谎，但我不想直接揭穿
* 我想靠近你，但我怕暴露自己更在乎
* 我在威胁你，但我保持表面温和
* 我想拒绝你，但关系压力让我不能直说

---

## 3. 拆书总方法：点、线、面

本 Skill 使用“点、线、面”三层拆解法。

---

## 4. 点：拆最小写作单位

“点”是章节中可以被单独学习的最小技法单位。

### 4.1 人物点

每章至少观察以下人物点：

| 人物点  | 拆解问题                   |
| ---- | ---------------------- |
| 欲望   | 这个人物此刻最想要什么？           |
| 恐惧   | 他最怕什么发生？               |
| 面具   | 他想让别人以为自己是什么样？         |
| 遮掩   | 他不想让别人知道什么？            |
| 破绽   | 哪个动作、台词、沉默暴露了他？        |
| 价值排序 | 利益、尊严、亲情、权力之间他怎么选？     |
| 习惯动作 | 紧张、撒谎、愤怒时身体如何反应？       |
| 语言纹路 | 他是短句、反问、讨好、绕弯、命令，还是沉默？ |

### 4.2 对话点

每段关键对话至少拆以下六点：

| 对话点 | 拆解问题               |
| --- | ------------------ |
| 目的  | 这句话想达成什么？          |
| 权力  | 谁在上风？谁在下风？         |
| 潜台词 | 他说出口的是什么？没说出口的是什么？ |
| 情绪  | 这句话背后的情绪是什么？       |
| 信息  | 这句话释放了什么新信息？       |
| 转折  | 这句话是否改变局势、关系或情绪？   |

### 4.3 场景点

每个关键场景至少拆：

* 场景开场状态
* 场景中每个人的目标
* 人物之间的阻碍
* 对话或行动中的攻防
* 信息暴露点
* 情绪变化点
* 场景结束状态

---

## 5. 线：拆连续变化

“线”是从一个点到另一个点的变化。

### 5.1 人物线

观察人物是否发生阶段性变化：

* 从逃避到承担
* 从遮掩到暴露
* 从试探到行动
* 从自保到选择他人
* 从被动承受到主动争夺
* 从相信到怀疑
* 从压抑到失控

拆解时必须回答：

```text
人物初始状态是什么？
什么压力逼他变化？
他做了什么选择？
这个选择付出了什么代价？
这一章后，他和前一章相比有什么变化？
```

### 5.2 关系线

人物必须在关系中显形。

每章要观察重要关系是否变化：

* 父子 / 母女：控制、亏欠、误解、和解
* 师生：规训、传承、压迫、超越
* 兄弟：竞争、义气、嫉妒、牺牲
* 男女：试探、靠近、错位、破裂
* 上下级：权力、服从、利用、反抗
* 敌人：压迫、镜像、理解、决裂

拆解关系线时必须回答：

```text
开场时两人是什么关系状态？
这场对话中谁想改变关系？
谁在抵抗？
谁占上风？
最后关系更近了、更远了，还是更复杂了？
```

### 5.3 对话线

一场好对话不能原地打转。

对话线可按以下结构拆：

```text
开场状态
→ 试探
→ 冲突
→ 遮掩
→ 破绽
→ 暴露
→ 反转
→ 结束状态
```

每段关键对话必须判断：

```text
这段对话前后，人物关系是否改变？
读者是否获得新信息？
人物是否暴露了自己不想暴露的东西？
局势是否被推进？
```

---

## 6. 面：拆系统能力

“面”是章节背后的完整写作系统。

### 6.1 人物面

观察本章如何服务人物群像：

* 主角是否只是被剧情推着走？
* 配角是否有自己的欲望？
* 对手是否只是工具人？
* 人物之间是否有互相塑造？
* 同一人物面对不同对象时是否呈现不同面孔？

### 6.2 对话面

观察作品是否形成语言系统：

* 年龄差异
* 阶层差异
* 权力差异
* 亲密度差异
* 性格差异
* 场景差异

要求：

```text
遮掉人物名，是否还能分辨是谁在说话？
```

如果所有人物都像作者本人说话，应标记为“语言同质化风险”。

### 6.3 主题面

观察人物选择背后的价值问题：

* 尊严和利益如何冲突？
* 亲情和自由如何冲突？
* 成功和代价如何冲突？
* 爱和控制如何混杂？
* 复仇和毁灭之间的边界在哪里？

高质量拆书不能只拆“剧情发生了什么”，还要拆“人物选择暴露了什么人生问题”。

## 7. 单章拆解流程

每个 chapter worker 每次只处理一章。

### 7.1 输入

```json
{
  "book_id": "string",
  "book_name": "string",
  "chapter_no": 1,
  "chapter_title": "string",
  "skill_id": "book-dialogue-research",
  "analysis_focus": [
    "character",
    "dialogue",
    "relationship",
    "scene_conflict"
  ]
}
```

### 7.2 执行步骤

1. 从 MCP 获取指定章节正文。
2. 快速识别本章主要人物和关键场景。
3. 找出本章最值得学习的 3–8 个片段。
4. 对每个片段按“点、线、面”拆解。
5. 提炼可迁移 micro-skill。
6. 生成原创示例。
7. 做质量自检。
8. 写入 session workspace。
9. 只返回摘要和产物引用。

## 9. 批次合并流程

每 5–10 章形成一个 batch。

batch merger 不读取小说正文，只读取 chapter worker 产物。

### 9.1 合并任务

1. 读取本批所有 `chapter_research.json`。
2. 统计所有 micro-skills。
3. 删除重复、泛泛、不可迁移的 skill。
4. 按场景类型聚类。
5. 提炼本批最有价值的 5–12 条通用技法。
6. 生成 `batch_research.md`。
7. 生成 `skill_delta.json`。
8. 生成或更新 `current_skill.md`。
9. 给下一批提出观察重点。

### 9.2 聚类维度

至少按以下维度聚类：

* 上位者压迫下位者
* 下位者试探上位者
* 聪明人互相试探
* 亲密关系中的软冲突
* 家庭关系中的控制与亏欠
* 师徒 / 长幼规训
* 交易谈判
* 群体围观中的面子攻防
* 危机中的快速决策
* 信息差制造误判
* 隐瞒秘密时的对话绕行
* 关系破裂前的最后试探

## 11. 质量标准

单章结果必须满足：

* 至少 3 条 micro-skills。
* 每条 micro-skill 必须有操作步骤。
* 每条 micro-skill 必须有原创示例。
* 必须包含人物行为证据。
* 必须包含至少一个对话权力关系分析。
* 必须包含至少一个潜台词分析。
* 必须包含至少一个关系变化或情绪转折。
* 不得大段引用原文。
* 不得只写“推动剧情、塑造人物、制造冲突、增强代入感”等泛话。

不合格特征：

```text
这段对话推动了剧情。
这个人物很立体。
这里表现了人物性格。
这一章节奏很好。
这段对话很自然。
```

这些都是低质量判断，必须继续追问：

```text
怎么推动？
靠哪句话？
谁在试探谁？
谁占上风？
人物隐藏了什么？
关系前后有什么变化？
这能迁移成什么写作动作？
```

---

## 12. 禁止事项

严禁：

* 把拆书变成剧情复述。
* 把原小说人物名固化进通用 skill。
* 把原小说设定直接当成技法。
* 大段摘抄原文。
* 每章只输出空泛总结。
* 用“人物鲜明”“对话自然”“节奏紧凑”这类空话代替分析。
* 让 Manager 读取章节正文。
* 让 Merger 读取小说正文。
* 把 raw chapter text 提交给父 workspace。
* 默认发布到正式 Skill；必须先进入 session workspace，用户确认后再发布。

## 13. 推荐工作流

```yaml
workflow:
  name: book-dialogue-research
  default_batch_size: 10
  default_chapter_granularity: chapter
  default_max_concurrency: 5

  stages:
    - id: locate_book
      type: mcp_tool
      tool: list_split_books
      output:
        - book_id
        - book_name
        - chapter_count

    - id: init_session_run
      type: workspace
      action: init_run

    - id: chapter_research
      type: fan_out
      worker: book_chapter_research_worker
      granularity: chapter
      max_concurrency: 5
      input:
        - book_id
        - book_name
        - chapter_no
        - skill_id
      output:
        - chapter_research_ref
        - chapter_summary_ref

    - id: batch_merge
      type: sub_agent
      worker: book_batch_research_merger
      input:
        - chapter_research_refs
        - skill_id
      output:
        - batch_summary_ref
        - batch_research_ref
        - skill_delta_ref
        - current_skill_ref

    - id: quality_check
      type: rule_check
      rules:
        - micro_skill_count_per_chapter >= 3
        - original_examples_required == true
        - raw_quote_risk != high
        - generic_risk != high

    - id: user_decision
      type: publish_or_discard
```

## 14. 给 Agent 的执行提醒

### Manager

你只负责流程：

* 查书
* 拆任务
* 建 run
* 调 worker
* 调 merger
* 返回 refs
* 请求用户确认发布或丢弃

你不要分析正文。

### Chapter Worker

你只负责一章：

* 读一章
* 深挖一章
* 写产物
* 返回 refs

你不要决定全局流程。

### Batch Merger

你只负责合并：

* 读 chapter 产物
* 去重
* 聚类
* 抽象
* 生成 batch skill

你不要读原文。

## 15. 最终目标

本 Skill 的最终产物不是“某本小说分析报告”，而是一套可迁移的写作能力。

一轮拆书结束后，应该得到：

```text
从具体章节中提炼出的：
- 人物塑造方法
- 对话描写方法
- 关系推进方法
- 场景冲突方法
- 常见错误与修正方式
- 可用于新小说创作的操作步骤
```

最终 Skill 要能回答：

```text
如果我要写一个自卑的人，如何不用形容词写出来？
如果我要写一场上下位对话，如何让权力关系通过台词显形？
如果我要写男女试探，如何让他们不直接表白却产生张力？
如果我要写家庭饭桌暗战，如何让每句话都有潜台词？
如果我要写人物关系变化，如何让一场对话前后状态不同？
```
