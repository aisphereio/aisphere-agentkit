# 全文压缩-仿写-差距归因-技能提炼 Skill

## 1. 定位

本 Skill 用于把一篇完整文本拆成可迁移的写作能力：

1. 压缩原文结构；
2. 抽取知识点和信息层级；
3. 提炼风格指纹；
4. 生成隔离仿写 brief；
5. 在不看原文的条件下写一版同类文本；
6. 比较原文压缩产物与仿写稿的差距；
7. 把差距沉淀成下一轮可执行 Skill。

它不是“改写原文”，也不是“洗稿”。它训练的是结构迁移、知识组织、叙事动作、论证动作、风格控制与自我评估。

---

## 2. 输入类型

可以处理以下输入：

- 小说章节或全文；
- 文章、报告、课程稿、演讲稿；
- 拆书材料；
- 用户提供的参考风格文本；
- 已切分的章节资产；
- 上传的 txt/md 文本。

如果输入很长，必须先分块；如果输入较短，可以单块处理。

---

## 3. 四层压缩法

### 3.1 结构压缩

结构压缩回答：这篇文本是怎样一步步让读者读下去的。

需要抽取：

- 开头如何建立问题、压力、好奇心或目标；
- 每一段/每一场的功能；
- 信息如何逐层释放；
- 冲突或论证如何升级；
- 关键转折点在哪里；
- 结尾如何收束或制造下一步期待。

错误压缩：

```text
这部分讲了主角遇到困难，然后解决困难。
```

正确压缩：

```text
这部分先让角色被误判，随后给出一个小证据但不立即解释，再让旁观者反应放大压力，最后用一个可验证动作反转局面。
```

### 3.2 知识点压缩

知识点压缩回答：这篇文本真正依赖哪些信息、判断和隐含前提。

需要区分：

- 主干概念：没有它文本就站不住；
- 支撑概念：用于解释主干；
- 例子材料：用于证明或呈现；
- 隐含前提：作者没有明说，但读者必须接受；
- 信息顺序：哪些必须先讲，哪些必须延迟。

不要把所有信息平铺成清单。知识点必须有层级。

### 3.3 风格指纹压缩

风格指纹不能写成“细腻、紧张、有代入感”这类形容词，必须写成可执行参数。

可观察维度：

- 平均句长：短句密集还是长句解释；
- 段落长度：一段承载一个动作还是多个动作；
- 对白比例：对白推进还是叙述推进；
- 解释密度：直接解释多，还是通过动作暗示；
- 情绪显性度：明说情绪，还是通过反应呈现；
- 信息释放：先给结论、先给现象、先给冲突，还是先给背景；
- 转折方式：反问、证据、动作、旁观者反应、概念重定义。

### 3.4 技能压缩

技能压缩回答：这篇文本中哪些写法能被另一个写作 Agent 复用。

每个技能必须包含：

- 技能名称；
- 解决的问题；
- 适用场景；
- 操作步骤；
- 失败模式；
- 验收标准；
- 可替换模板。

错误技能：

```text
要写出冲突感。
```

正确技能：

```text
先让一方拥有评价权，再让被评价者必须解释，随后用旁观者沉默确认压力，最后让被评价者拿出一个可验证动作夺回解释权。
```

## 4. 隔离仿写规则

仿写 worker 只能读取：

- compressed brief；
- knowledge map；
- style fingerprint；
- skill candidates；
- 用户指定的新题材或目标。

仿写 worker 禁止读取：

- 原文全文；
- 原文分块；
- 大段证据；
- 原文人物名、地名、专有桥段。

这样才能判断压缩和技能是否真的可执行，而不是靠模型记住原文。

仿写目标是：

- 同类结构效果；
- 同类知识组织；
- 同类节奏和信息密度；
- 同类情绪或论证推进；
- 新文本、新素材、新表达。

---

## 5. 差距归因框架

评估时不要只说“像/不像”“文笔好/不好”。必须把差距归因到可修复位置。

### 5.1 brief_gap

压缩 brief 漏掉关键任务，导致写作 worker 不知道该完成什么。

典型表现：

- 仿写稿有内容，但没有原文的结构转折；
- 场景/段落顺序变松；
- 缺少开头压力或结尾钩子；
- 关键人物/概念状态没有交代。

修复方式：补充结构动作、目标、约束和结尾功能。

### 5.2 knowledge_gap

知识地图没有给清楚主干和支撑关系，导致仿写稿信息空、虚或乱。

典型表现：

- 只堆概念，没有因果；
- 例子无法支撑观点；
- 论证顺序不对；
- 小说中则表现为资源、规则、动机不清。

修复方式：重建知识层级和信息释放顺序。

### 5.3 style_gap

风格指纹太抽象，写手无法执行。

典型表现：

- 原文短促，仿写拖沓；
- 原文靠动作暗示，仿写直接解释；
- 原文信息密集，仿写空话多；
- 原文对白有压迫感，仿写对白像聊天。

修复方式：把风格词改成可执行参数。

### 5.4 skill_gap

技能候选太泛或缺步骤，导致写手不知道怎么落地。

典型表现：

- 技能写着“制造反转”，但没说反转前要埋什么；
- 技能写着“人物有层次”，但没说通过什么动作呈现；
- 技能写着“对话有潜台词”，但没说谁隐藏什么、谁逼问什么。

修复方式：每条技能补“适用条件 -> 操作步骤 -> 失败模式 -> 验收标准”。

### 5.5 execution_gap

brief 和 skill 已经给出，但写手没有遵守。

典型表现：

- 已要求短句，仿写仍长段解释；
- 已要求先压后放，仿写开头直接解决；
- 已要求用旁观者反应校准权力差，仿写没有旁观者。

修复方式：重试 writer，或把规则改成更硬的检查清单。

### 5.6 originality_risk

仿写稿太接近原文，存在复刻风险。

典型表现：

- 人物关系、事件顺序、专有名词、独创表达过近；
- 只是换词，没有换素材；
- 原文桥段被保留。

修复方式：增加反过拟合规则，强制换素材、换场景、换人物功能组合。

---

## 6. Gap 评分

每个 gap 用 0-5 分：

- 0：没有明显缺口；
- 1-2：轻微影响；
- 3：明显影响同类效果；
- 4-5：导致样稿核心失败。

总体决策：

- `accept_sample`：样稿完成同类效果，可以沉淀技能；
- `refine_brief`：先改压缩 brief；
- `refine_knowledge_map`：先改知识地图；
- `refine_style_fingerprint`：先改风格指纹；
- `refine_writer_skill`：先改技能候选；
- `retry_writer`：规则够了，是写手执行问题；
- `request_human_review`：需要人工判断是否值得提升为正式 Skill。

---

## 7. 正式 Skill 提炼规则

从 gap 中提炼 Skill 时，必须遵守：

1. Skill 正文必须 source_free，不依赖源文本才能理解；
2. 不把原文角色名、地名、组织名、章节号写入正式规则；
3. 不把“这篇文章/这一章如何写”当成通用 Skill；
4. 每条规则必须可执行；
5. 每条规则必须有失败模式；
6. 每条规则必须有验收标准。

推荐 Skill 结构：

```markdown
# Skill 名称

## 触发条件
什么时候使用。

## 写作目标
读者应感受到什么。

## 核心原则
3-6 条可迁移判断。

## 执行流程
从判断场景到产出文本的步骤。

## 技法模块
每个模块包含适用场景、操作步骤、替换模板、失败模式、验收标准。

## 反过拟合规则
哪些内容必须替换或删除。

## 自检清单
写完后如何判断是否达标。
```

## 8. 输出产物约定

一次完整 run 建议产出：

```text

batch_0001/batch_summary.json
batch_0001/batch_analysis.md
batch_0001/skill_delta.json
batch_0001/current_skill.md
...
current/compressed_brief.md
current/knowledge_map.json
current/style_fingerprint.json
current/imitation_brief.md
current/skill_candidates.md
current/imitation_draft.md
current/imitation_meta.json
current/gap_report.json
current/gap_report.md
current/skill_delta_after_gap.md
current/next_iteration_plan.md
```

对用户展示时只展示摘要和 refs，不直接贴出大文件。
